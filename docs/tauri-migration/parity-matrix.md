# Desktop parity matrix

Reference: commit ef401b20cb2a5960278a8e7ab2c0e96d8f759aeb. Paths below are repository-relative.

## Evidence rules

All capabilities below are pending implementation and pending runtime verification on Linux, Windows and macOS unless explicitly stated otherwise. This inventory is source evidence, not proof that the reference passes its own tests. A test path identifies a reusable reference check, not an executed test. Each row requires real Tauri execution evidence on each supported OS, including failure cases. Existing reference restrictions remain restrictions rather than becoming invented support.

The generated [IPC inventory](ipc-inventory.json) contains every member exported by the main/helper command and event registries, plus the native import preload wrapper: **153 commands and 24 events**, 177 unique entries. Empty legacy-db/workspace event namespaces are recorded, not invented. Each member records its definition at the fixed reference commit. Implementation and verification records must be maintained separately from this immutable reference inventory.

## Processes and integration surfaces

- Main Electron process: application lifecycle, window/webview/tab ownership, navigation security, authenticated network transport, credential storage, menus/tray, updates, popups and recording coordination.
- Helper process: SQLite v1/v2, workspace backups, native import dialogs, folder synchronization, Mermaid/Typst preview. Renderer-helper RPC uses transferred MessagePorts; helper-main RPC exposes selected dialog/shell/path operations.
- Preload: exposes __appInfo, __apis, __events and __sharedStorage only to internal origins; bridges worker ports and translates browser File selections to native import paths. These are contracts to replace, not Electron code to embed in Tauri.
- Renderers: app, shell, popup and backgroundWorker entry points under packages/frontend/apps/electron-renderer/src; PDF, workspace-profile and turbo-painter workers from core. Startup binds native DB v1/v2 APIs before rendering.
- Shared frontend: React/TypeScript + BlockSuite remain in scope unchanged in functionality; desktop adaptations under packages/frontend/core/src/modules/desktop-api, modules/workbench/view/desktop-adapter.ts and blocksuite/view-extensions/electron need a runtime-neutral boundary.
- Shared storage has synchronous reads during bootstrap, revision ordering, source suppression and cross-view observation. Tauri must hydrate before importing the application rather than exposing uninitialized state.

## Data and security boundaries

- Electron sessionData holds workspaces/userspaces/<peer>/<normalized-id>/storage.db, legacy <space>/<id>/storage.db, deleted-workspaces and recordings. Paths come from helper/workspace/meta.ts and recording/feature.ts. A new Tauri app identifier must not write to these locations by accident.
- userData holds config.json, global-state.json, global-cache.json, auth-sessions.json, installation-id and workspace-byok-keys.json. Copying encrypted safeStorage bytes is not an interoperable keychain migration.
- Reuse the existing SQL migrations and CRDT encodings; back up WAL-backed databases consistently rather than copying storage.db alone while the reference app is open. Tests need interruption, duplicate migration, invalid schema and restore scenarios.
- Tauri should replace main/helper responsibilities with Rust services and explicit commands/events, not spawn Node/Electron for parity. Native nbstore's use-as-lib feature is a starting point, not proof of N-API independence: lib.rs still imports napi types and Cargo.toml enables affine_common/napi unconditionally.
- Remote document embeds, external navigation, external links and OAuth browser windows must never receive native command capabilities. Validate command arguments and per-view ownership, and constrain paths to app-owned or user-granted roots.

## Verification and environment record

The generator reads only committed Git objects at the reference revision and resolves imports, aliased reexports, full reexports and literal event names with the TypeScript parser. Unknown API shapes fail closed. To regenerate the immutable inventory:

    yarn node tools/tauri-migration/inventory.mjs

To verify completeness and source locations:

    yarn node --test tools/tauri-migration/inventory.test.mjs

Before workspace dependency installation, the host parser can be used without changing the repository:

    NODE_PATH=/usr/lib/node_modules node --test tools/tauri-migration/inventory.test.mjs

The five inventory tests passed with Node 24.22.2 and host TypeScript 6.0.3. This is evidence about the inventory only. Application unit/E2E tests and the reference GUI have not yet run. The repository requests Node 22 and Yarn 4.18.0; the checked-in Yarn executable runs. Rust 1.97.1's explicit toolchain directory is incomplete, but rustup run 1.97 resolves a working rustc/cargo 1.97.1; a per-command override can avoid modifying the original checkout. GTK/WebKitGTK are installed. The project filesystem has about 16 GiB free; /tmp has over 400 GiB available for disposable build output. No Windows/macOS machine or runner has yet been verified.

## Completion gate

Do not mark any API or capability complete merely because it is enumerated, mocked, mapped to an unimplemented command or inherited from shared TypeScript. A separate result ledger must attach implementation paths, test commands, revision and OS/architecture evidence. All P01–P28 and 177 API entries must be accounted for before final parity audit. New upstream changes are outside this fixed baseline until explicitly incorporated.
